# fast-jev-compaction Claude Code mod

This plugin uses Claude Code function hooks to replace a compaction with the
original messages, with the tool outputs Jev judged no longer needed cut to a
note. `hooks/fast-jev.ts` is a thin adapter: it reads the plugin options,
finds the TypeSafe key, hands `session.compact` transcripts to the
`fast-jev-compaction` library in `src/` (the plugin folder is the repository
root, so the hook imports it directly) and maps the result back onto session
messages. User and assistant text is never touched. Jev is sent the whole
conversation as `state` (tool outputs replaced by a one-line note) and, for
every tool call outside the pinned first and newest messages, two questions:
whether the call should stay and whether its full output should stay. An
item is kept when Jev's probability reaches `keepThreshold`; a dropped result
is truncated to its first `truncateHeadChars` characters plus a one-line note,
and a call Jev rates as unneeded stays whole with its output replaced by a
one-line note (`dropCalls: true` removes it with its result instead). Only
tool-result messages are rebuilt; a message holding a call keeps the engine's
handle, so a parallel response is never split (upstream #137).

The state is fitted into `maxStateTokens` in stages: tool inputs are
truncated, then long texts are abridged (oldest first, pinned messages last),
then old messages collapse to a `[… N chars omitted …]` note, then old tool
calls shrink to one line each, then old call-less messages are left out and
runs of old call-only messages fold together. If even that does not fit, the
calls are asked in windows, each with its own fitted state. Questions are split
into as many requests as needed so each request (state plus questions) stays
under `maxRequestTokens` and holds at most 128 questions; the state is resent
with every request, at most four run at once. An output an earlier compaction
already reduced is not asked about again. Secret-shaped values are redacted
from everything sent to Jev, and so are the `settings.env` values whose name
says KEY, TOKEN, SECRET, PASS, AUTH or CRED or which look like a token; the
transcript itself keeps them. Token counts are
estimated without a tokenizer, calibrated to land a little above what Jev
reports.

The mod is an early-access Claude Code function-hook module. The checked-in
type reference was generated by Claude Code **2.1.274**. Enable the function
hooks surface before installing or loading it:

```sh
export CLAUDE_CODE_ENABLE_FUNCTION_HOOKS=1
export TYPESAFE_API_KEY="<your TypeSafe key>"

claude plugin marketplace add Lexus2016/fast-jev-compaction
claude plugin install fast-jev-compaction@lexus2016
```

For local development:

```sh
CLAUDE_CODE_ENABLE_FUNCTION_HOOKS=1 claude --plugin-dir .
```

## Configuration

The plugin declares these `userConfig` values in
`.claude-plugin/plugin.json`:

| Option | Default |
| --- | ---: |
| `keepThreshold` | `0.5` |
| `preserveRecentMessages` | `6` |
| `compactAtPercent` | `60` |
| `minReductionRatio` | `0.25` |
| `builtinFallback` | `auto` |
| `dropCalls` | `false` |
| `compactionTimeoutMs` | `60000` |
| `maxStateTokens` | `25000` |
| `maxRequestTokens` | `30000` |
| `truncateHeadChars` | `300` |
| `model` | `jev-latest` |
| `logDecisions` | `false` |
| `keychainService` | none |
| `ledgerDir` | `~/.fast-jev/events` |
| `excludePaths` | none |
| `statusLine` | `true` |
| `decideTool` | `true` |
| `decideReminder` | `auto` |

The TypeSafe key can be supplied as the sensitive `apiKey` plugin option or
through `TYPESAFE_API_KEY`. The environment variable is the recommended
development setup.

Every option except `apiKey`, `keychainService`, `compactAtPercent`,
`minReductionRatio`, `builtinFallback`, `compactionTimeoutMs`, `model`,
`logDecisions`, `ledgerDir`, `excludePaths`, `statusLine`, `decideTool` and
`decideReminder` is passed straight to the library; see the root README for what they do. Subagent and
fork compactions (`agentId`) go to the next handler untouched, and a
`precompute` is skipped. If Jev fails, the response is malformed, the key is
unavailable, or the estimated reduction is below `minReductionRatio`, what
happens next depends on the compaction's `trigger`. On every trigger, if the
stubs alone free too little, the same answers are applied with the stubbed
calls removed (no new Jev request) and installed if that clears the minimum.
If it still does not, with `builtinFallback` at `auto` only Claude Code's own
compaction (`auto`: its threshold, or a prompt too long, when the conversation
has to shrink) logs a fallback and delegates to Claude Code's built-in
compaction; `/compact` (`manual`) and a plugin's request (`plugin`, including
this plugin's `turn.complete` one) answer `{ skip }` instead, so the
conversation stays as it is and Claude Code shows why, with what removing the
calls would have freed.
`always` delegates on every trigger, as upstream did; `never` on none. The
outcome is shown as a toast and logged as one line with the reduction only.
Setting `logDecisions` adds the per-reason counts, state size and request
count to that line, the number of redacted values, and a per-call
`decisions:` line with both probabilities for diagnosis. The `turn.complete`
hook requests compaction when `context.percent` reaches `compactAtPercent`, for
a main-agent answer only, with an in-flight guard. When that request is
skipped, the hook waits until the context has grown by another 10 percentage
points, or dropped below `compactAtPercent` again, before it asks again. In a
headless session, where Claude Code refuses `$.session.compact`, it stops
asking after the first refusal.

The hook waits at most `compactionTimeoutMs` for the Jev round, across all
request batches. A timeout is handled like any other failure: an engine
automatic compaction falls back to the built-in summary, and `/compact` or a
plugin request returns a skip notice and leaves the conversation unchanged
(with `builtinFallback: auto`). This bounds
the Jev wait, not the duration of a built-in summary. The host HTTP interface
does not expose per-request cancellation, so in-flight requests may still
finish; their late results cannot replace the conversation. Zero, negative
and non-finite timeout values use the default.

Run `npm run test:hooks:host` with a function-hook-capable Claude Code CLI to
exercise the deadline through Claude Code's actual hook dispatcher and a
virtual clock. The tests use synthetic messages and mocked HTTP responses
and make no model requests. `npm test` continues to run the fast library and
adapter tests without a Claude CLI.

## Key from the Keychain, ledger, excluded folders, status line

With `keychainService` set, a key found in neither the `apiKey` option nor
`TYPESAFE_API_KEY` is read from the macOS Keychain
(`security find-generic-password -s <service> -w`), so it has to be in no
settings file and no shell profile:

```sh
security add-generic-password -U -s typesafe-jev -a "$USER" -w   # prompts for the key
claude plugin configure fast-jev-compaction@lexus2016 --values-stdin <<< '{"keychainService":"typesafe-jev"}'
```

Every compaction outcome (`compacted`, `calls-removed`, `fallback`,
`skipped`, `excluded`) is written as one JSON file under `ledgerDir`: the
surface (`t3-code` when T3 Code started the session, else Claude Code's
entry point such as `cli` or `sdk-ts`), the session id, the working directory's last segment, the trigger, message and
character counts before and after, `tokensFreed` (characters / 4, an
estimate), the decision counts, the number of Jev requests and the input
tokens Jev reported for them (`jevTokensReported: false` marks an estimate,
requests times the state size, when Jev reported none; a round that failed
records none). No message text and no tool input is written, and a
provider's error body is cut to its status (`Jev request failed (401)`).
A skip or a fallback records `tokensFreed: 0`: nothing was installed. What
the built-in summary then freed is not measured.

A session is never sent to Jev when one of the `excludePaths` entries
(case-insensitive, split at commas) is found in its working directory, in
its repository's root (the main working tree's, for a worktree) or in its
`origin` URL: the hook logs it, records an `excluded` event without the
folder's name and hands the compaction to Claude Code's built-in summary,
whatever `builtinFallback` says. The `turn.complete` hook never requests a
compaction for such a session, so it is compacted when Claude Code's own
threshold says so, not at `compactAtPercent`. With entries set, a session whose
directory cannot be read counts as excluded. The check is where the session
runs; a file read from an excluded folder in a session running elsewhere is
not recognised, and neither is a copy of the folder under another name.

`statusLine` pins one line under the prompt, refreshed at the session's
start, after every main-agent answer and after every installed compaction
(the percentage reappears with the next answer):
`Jev ● armed · context 34% · compacts at 60% · freed ~120k tokens in 3 runs`.
Headless surfaces (`-p`, the SDK) have no status line. The ledger and the
status line wait at most two seconds for a write or the Keychain.

## The decision tool

With `decideTool` on, the session offers the model
`mcp__fast-jev-compaction__jev_decide`: a `question`, optionally 2 to 8
`options` (`name`, `description`), and a `context` with the facts. Without
options the question is yes/no (a `noul` question; the result gives the
probability of yes, and "cannot tell" when it rounds to more than 35% and
less than 65%); with options it is a `choice` question (the chosen option,
its confidence and every option's probability; a confidence under 65% is
called low). Jev gets these three fields as the request and nothing else of
the conversation; they go through the same redaction as a compaction (the
options travel as `A`, `B`, ... with their names in the redacted values).
A session in an excluded folder is not offered the tool, and one without a
key gets a result saying Jev was not asked. A failure, or no answer within
20 seconds, never fails the call: the result says so and tells the model to
decide without it.

Every decision shows as a tool call in the transcript and as one
`Jev decided: …` log line, and is recorded in the ledger as a `decision`
event with its kind (`yesno` or `choice`) and the tokens Jev reported; the
question, the options, the context and the answer are not written.

With `decideReminder` at `auto`, a `prompt.submit` hook attaches a context
block (read by the model, not shown to the user) to a prompt the person sent
(typed, sent over Remote Control, or handed in by an SDK host) that looks
like a decision, a comparison or a research task: a "should we", a "which",
an "or" in a question, "compare", "recherchiere" and the like, in German or
English. The block tells the model to call `jev_decide` before answering and
to begin its answer with `JEV: <answer> (<probability>)`, or with
`JEV: nicht gefragt (<why>)` when there was no decision or the tool did not
answer. `always` attaches it to every such prompt and leaves the judgement to
the model; `off` attaches nothing. The pattern is generous and the model may
still not follow the reminder: it makes a consultation likely, not certain.
Slash commands, prompts from other sessions, schedules and notifications, and
sessions in excluded folders get no reminder.

## Scope and caveat

Function hooks are early access and may change between Claude Code releases.
This mod uses the generated declarations from 2.1.274 in
`types/claude-code.d.ts`; regenerate and review that file after a
Claude Code upgrade.
